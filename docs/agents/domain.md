# Domain Docs

Read the domain docs that apply to the work before exploring the code.

## Files

- `GLOSSARY.md` at the repo root is the single-context glossary.
- `docs/adr/` holds architecture decision records. Read decisions that touch the work.

If a file or directory does not exist yet, proceed without creating it. Add domain terms and decisions when they are resolved.

## Use the glossary

Use the terms defined in `GLOSSARY.md` in issues, proposals, hypotheses, and tests. If a needed concept is missing, note the gap rather than inventing a competing term.

## Flag conflicts

If proposed work conflicts with an existing ADR, state the conflict rather than silently overriding it.
