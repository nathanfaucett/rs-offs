# 02: Browser backend and WebAssembly surface

**What to build:** A browser application can open a File System in a page or worker, write
and read Content Revisions, and reconcile over a JavaScript-supplied Transport. The
browser backend stores Content Revisions in the Origin Private File System and metadata
and catalog in two separate physical browser key-value stores, and the File System is
exposed to JavaScript through WebAssembly bindings with generated TypeScript
declarations.

**Blocked by:** 01: Make the File System core storage-agnostic and wasm-compilable

**Status:** ready-for-agent

- [ ] The browser backend stores Content Revisions in the Origin Private File System
      obtained from the navigator Storage Manager, laid out per filesystem root.
- [ ] Publishing a Content Revision writes its bytes first and commits the metadata that
      selects it only afterwards; an interrupted write leaves a revision that no reader can
      observe.
- [ ] The browser backend never relies on a rename or move primitive in the Origin Private
      File System.
- [ ] Offset writes and appends work in the browser by reading the previous revision,
      applying the modification, and writing the new revision whole.
- [ ] Streaming reads yield asynchronous chunks from the content port.
- [ ] File System metadata and the File System Resource catalog use two separate physical
      browser key-value stores, opened under distinct database names.
- [ ] Exclusive ownership across tabs of the same origin is enforced with an exclusive
      Web Lock scoped to the origin and filesystem root.
- [ ] Retirement is recorded as a tombstone in the browser key-value store and is observed
      by every tab of the origin.
- [ ] The WebAssembly module opens a File System, reads, writes, scans, syncs, and closes
      entirely through promises, in both a Window and a Dedicated Worker context.
- [ ] TypeScript declarations for the exposed API are generated by the binding tool, not
      hand-written.
- [ ] A Transport and a File Session Service supplied from JavaScript satisfy the same
      public contracts as the native ones.
- [ ] A dependency-graph check fails the browser build if a native storage crate appears in
      the browser dependency graph.
